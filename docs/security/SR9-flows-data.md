# SR9: analysis flows, uploads, external PostgreSQL (M2a)

Scope: `backend/app/flows/**`, `app/services/{flows,files,data_connections}.py`, `app/api/routes/{flows,data}.py`,
`app/api/schemas_flows.py`, the multipart exception in `app/api/security.py`, and the related tests.
Method: code read plus probes against the local Docker DB only (127.0.0.1:5433, `dataforce_test`, in-process
fakes on loopback). Probe sources: scratchpad `probe_pg.py`, `probe_pg2.py`, `probe_eng.py`, `probe_eng2.py`,
`probe_up.py`, `probe_api.py`, `probe_api2.py`. No application code was changed. Versions: openpyxl 3.1.5 with
defusedxml 0.7.1 installed, pandas 3.0.6, psycopg 3.3.6, starlette 1.8.0, python-multipart 0.0.32.

## Confirmed protections (probed unless marked "code")

- Workspace isolation: a `file_id` or `connection_id` of workspace a2 inside a graph run in workspace a1 gives "the uploaded file no longer exists" / "the database connection no longer exists". Flow, file and connection ids across workspaces return 404 on get/delete/test/tables. `get_scoped` is used by every service (code).
- SQL by identifier: `table` goes through `sql.Identifier`; a payload `pg_class"; DROP TABLE x; --` gives "relation does not exist". Server rejects `FOR UPDATE`, data-modifying CTEs in the subquery, `lo_creat`, `nextval` in the READ ONLY transaction. `COPY`, `CALL`, `DO` and `SET` cannot appear inside the wrapped subquery. `set_config('transaction_read_only','off')` is refused. A `database` value containing `host=...` or a URL is treated as a database name (no conninfo injection).
- TLS policy: non-loopback hosts need `require`, `verify-ca` or `verify-full`, on create and on PATCH (`127.0.0.1.nip.io`, `0x7f.1` with `disable` give 422); enforced again at connect time (code).
- Timeouts and caps: `connect_timeout=10`, `statement_timeout` (`pg_sleep(8)` with 5 s limit was cancelled), `LIMIT max_rows+1` plus `fetchmany`, rows capped with a warning.
- Password: Fernet sealed, never returned (`has_password` only), not echoed in 422 bodies, `PgTarget.password` has `repr=False`, `sanitize_message` strips the password and URLs, a wrong password gives a message without it.
- Multipart exception: only `POST /api/w/{slug}/files` (exact regex); multipart on `/flows` returns 415, a trailing slash returns 415. Host allow-list, Origin and `X-DataForce` checks still apply (evil Origin 403, evil Host 400). Size cap: a 22 MB body (Content-Length) and a 30 MB chunked body without Content-Length both return 413; the route also reads at most `upload_max_bytes + 1`.
- Uploads: only `.csv`/`.xlsx`; zip magic, entry count, `xl/workbook.xml`, VBA and path checks; CSV binary/NUL sniff; names sanitised (`../x/people.csv` -> `people.csv`, `<script>` stripped); content stored as bytea and never served back; the file list defers `content`.
- XML: openpyxl uses defusedxml (installed); billion-laughs and external-entity sheets are refused.
- Code execution: no `eval`, `exec`, `DataFrame.query`, pickle, `read_pickle`, `read_html`, `read_json`, `read_sql` in scope (grep). Filter uses `regex=False`; computed columns are fixed ops.
- Verification: gates come from server settings (`gate_config_from_settings`); `RunRequest` has no gates field and forbids extras, so a request cannot lower them.
- Run rows: `params` hold target and node count; `result` holds statuses, row counts and error text (see SR9-10 for the text).

## Residual risks

- SR9-01 through SR9-08 should be fixed before M2a is called secure; SR9-01 first.
- Resource limits are cooperative (deadline between nodes only); the real fix is process isolation or per-block deadlines (SR9-04).
- The external database role is the actual security boundary; the app cannot guarantee read-only behaviour for a privileged role.
- No login before M3: every guard relies on loopback, Host, Origin and `X-DataForce`; SR9-02 is only reachable through those guards.
- `require` TLS accepts any certificate.

## Resolution

### Engine and blocks

- SR9-03 / SR9-04 (cooperative part): the engine passes `Ctx.deadline`; `Ctx.check()` raises "time limit reached" and is called per stats group, per bootstrap chunk (`blocks/_boot.py`, model bootstrap), before model encoding, per pivot and between k-means chunks (warm-started 20-iteration fits, max 300). Stats allows 50 groups. Median bootstrap work is bounded: rows x resamples x (groups + 1) above 2e8 lowers resamples (floor 200, with a warning); still above budget (25% slack) errors with "too many rows for a median comparison: filter or sample first". The rest/group bootstraps are computed once per group and reused. Regression tests in `tests/flows/test_sr9.py`. Not fixed here: the worker thread still cannot be killed inside a single sklearn/numpy call, and run concurrency limits belong to the service (other fixer).
- SR9-06: the engine traces `train` and `test` back through filter, sort and columns blocks; the model is `verified`-eligible only when both reach different ports of the same split block. Otherwise `not_verified` with "test rows may overlap the training rows: connect train and test from the same split block". The computed-from-target feature warning is accepted as not done (a computed column can legitimately use the target's inputs).
- SR9-07: `BlockOutput.rows_multiplied` is set by a join with more output rows than its left input and propagates to all descendants in the engine. Stats and model add "rows were duplicated by an upstream join, so n is inflated" (`not_verified`); the join adds a warning. Duplicate rows already present in a source are not detected (accepted).
- SR9-08: pivot view capped at 1,000 rows and 50,000 cells with a warning; flat output capped at `limits.max_rows`; more than 5M cells errors. `truncated_columns` is unchanged. Note the loader already caps input rows at `max_rows`, so the flat cap is defence in depth.
- SR9-09: encoded one-hot width capped at 500 with a clear error. Sparse output not adopted (the cap bounds memory).

### Sources and runs

- SR9-01: fixed. The wrapped query runs through a server-side cursor (extended protocol); the server answers "cannot insert multiple commands into a prepared statement" (mapped to "only one statement is allowed"). The scanner stays as defence in depth. Regression tests: `$$`, `$tag$`, comment and E'' payloads with `COMMIT; BEGIN READ WRITE; DELETE`; the scratch table stays intact.
- SR9-02: fixed. A PATCH changing host, port, database, username or sslmode without a new password answers 422 "re-enter the password when changing the server or user"; the stored password is never sent elsewhere (tested).
- SR9-04: fixed on the run side. `flow_max_concurrent_runs` slots (non-blocking semaphore, 409 `conflict`); a slot is released only when the worker thread really ends (also after a 504); the deadline travels in `FlowLimits.timeout_s`. Cooperative checks inside blocks belong to the engine fix.
- SR9-05: fixed. CSV header read first (at most 1 MB), more than 500 columns refused before pandas (80k-column header refused in under a second); fields over 1 MB refused.
- xlsx amplification: fixed. Streamed with `read_only=True`; refused past 500 columns or 50 M characters; rows capped at `max_rows`.
- SR9-10: fixed in sources. Server text of data errors (SQLSTATE classes other than 42) is replaced by "the query failed (SQLSTATE xxxxx)"; run rows and `last_error` store only these generic messages.
- SR9-11: partly. Client-side watchdog calls `conn.cancel()` after `timeout_s` + 1 s, so `set_config('statement_timeout', ...)` cannot run forever. Residual: `pg_terminate_backend` and side-effect functions remain callable; the role must be read-only and not superuser.
- SR9-12: fixed. Server-side cursor, chunks of 2000 rows, stop at `max_rows` or 200 MB (approximate), result marked capped.
- SR9-13: accepted. The 10x zip factor is kept (xlsx is now streamed, shared strings still loaded by openpyxl); the 50 M character cap bounds the frame.
- SR9-14: fixed. Connection failures always say "could not connect to host:port" whatever the cause; the duplicated prefix is gone. No private-range block (accepted: the tool is local-first).
- SR9-15: accepted. `require` keeps skipping certificate verification; `ConnectionOut` documents `verify-full`. Formula prefixes: no export exists, nothing done.
- Residual: the external role is still the boundary; the thread of a timed-out run keeps running until it ends (it holds its slot meanwhile).
