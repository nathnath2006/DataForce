# SR10: Company 360, public registry, AI settings and assistant

Reviewer: SR10, scope per brief (M2a contract sections 2, 5, 6). No application code was changed. Probe tests live in the scratchpad (`.../scratchpad/p/test_probe*.py`), run with the test DB, respx and the fake provider; no network, no dev DB.

## Confirmed protections (each probed or read)

- Workspace isolation: link to another workspace's company, 360, PATCH, DELETE, refresh-registry and ask (company and account of another workspace) all return 404. The same SIREN may exist in two workspaces; `find_by_sirens` and `build_context` filter by workspace.
- Registry: fixed base URL from settings (https enforced, no per-request host); `q` and `page` go through httpx `params` (a `q` of `x&per_page=1000&page=9#../../etc?y=1` stays inside `q`, `per_page` stays 10); the SIREN is only used as `q`. Redirect returns 502 (`follow_redirects=False`); a 2 MB body is refused at 1 MB with `Accept-Encoding: identity`; 10 s timeout; query at most 100 characters (422); 5 req/s throttle; 25 results at most.
- `dirigeants` and `finances` are never read: `parse_record` whitelists fields (a poisoned record leaked nothing in the JSON or DB). A head office or record whose `statut_diffusion` is not O drops address, postcode and city (probed for both levels).
- AI key: sealed with Fernet (`gAAAA...` in DB, plaintext absent); never returned by GET/PUT (no partial, no last digits); not in 422 messages (long, spaced, wrong-type and misplaced keys all probed; handler prints paths and messages only); not in caplog; `last_error` and the 502 message go through `sanitize_error`; the key is sent in an SDK header (Gemini `x-goog-api-key`), never in a URL; base URLs are hard-coded (no env redirect).
- Provider change without a new key: 422. Model id pattern `^[a-z0-9][a-z0-9.\-]{0,63}$` (no slash, colon, space or key shape). Test call: 5 output tokens, one attempt, `purpose=connection_test`.
- Assistant data: enriched emails and mobiles are not read (context probe: no `@`, no phone); only names, titles, deal figures, notes and comments are sent, matching the on-screen notice. Context capped by `assistant_max_context_chars` (default 40 000, max 400 000) and by item counts; oldest notes dropped first, `truncated` reported. Question and answer are not stored (only an `llm_call` row with tokens).
- Notes and comments: both are wrapped via `wrap_sources` with fixed ids (N#/M#); `<source`/`</source` variants (case, up to 16 spaces, fullwidth, NFKC) are neutralised to `&lt;`; the injected bodies stayed inside one block.
- Quotes: a quote is verified only inside the source cited (a comment's text cited as [N1] gave `verified:false`); unknown refs are removed from the answer.
- Cost abuse from a website: POST ask and POST ai/test with no headers, a foreign Origin, `Origin: null`, `text/plain`, or a foreign Host all return 403 or 400 with zero provider calls.
- `created_at`: not in any request schema (`extra="forbid"` gives 422 for a body field; a query-string `created_at` is ignored and the row gets the server time); only the service keyword exists and `_checked_time` rejects naive, future and (for corrections) older times.

## Residual risks

- The assistant is advisory: citations only prove that a ref exists (a note can contain "[F1]" and the model can cite it for an unrelated claim); a quote proves a string is present, not that it supports the claim.
- The numeric check is a heuristic (SR10-01); until fixed, "unverified_numbers empty" must not be read as "all numbers verified".
- Names and notes are third-party text sent to the user's chosen provider; the data notice covers it. Look-alike letters from other scripts are not folded (documented in `untrusted.py`).
- The registry may return personal data for sole traders in the name field; the whole API surface is loopback with no login before M3, so isolation between workspaces rests on slug scoping only.

## Resolution

All eight findings are fixed. Tests: `tests/assistant/test_sr10.py` (new), additions in `tests/api/test_ai.py` and `tests/api/test_companies.py`.

- SR10-01: `app/assistant/numbers.py` now examines digits glued to letters or currency (`EUR9999`, `9999EUR`, `€9 999`), scale words (`3 million`, `2,5 M€`, `3 mille`, `1.2bn`, milliard) and EN/FR number words (zero to twenty, tens, hundred/cent, thousand/mille, million, billion/milliard, compounds such as "twenty-five", "vingt-cinq", "quatre-vingt-dix", "vingt et un"). Only code-computed items (F, D, C, plus the dates of note headers) verify a number. A number found only in a note or comment goes to the new `AskOut.numbers_from_notes: list[str]` and the answer gets the line "Numbers as written in a note, not verified: ...". Ref-shaped markers (`[Z9]`) and list ordinals are ignored. Residual: "one"/"cent" are flagged like any number word; French "un/une" only after "et".
- SR10-02: single-quoted, curly single and existing quote styles are checked; apostrophes inside words are not treated as quotes.
- SR10-03: every CRM text in the context goes through `_neutral` (sanitize, then `<` and `>` become `&lt;` `&gt;`), notes and comments included.
- SR10-04: `app/assistant/ratelimit.py`, sliding one-hour window per workspace, `settings.assistant_max_asks_per_hour` (default 60); `ask` and `/ai/test` count; over the limit gives 409 `conflict`.
- SR10-05: SIREN is `[0-9]{9}` in the schemas, the registry client and the service.
- SR10-06: `llm_call.error` is passed through `sanitize_error` (keys masked, control characters replaced, 300 characters). `sanitize_error` also strips control characters now (a NUL in a provider message previously made the `last_error` insert fail).
- SR10-07: registry search is `POST /registry/search` with body `{q}`; the frontend `companiesApi.registrySearch` is updated.
- SR10-08: `RegistryCompany.protected` / `RegistryCompanyOut.protected`; `from-registry` and `refresh-registry` answer 409 "this registry record is protected (non-diffusible)". Search still lists the record.
